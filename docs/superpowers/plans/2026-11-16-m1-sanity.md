# M1 — Sanity: modello dei contenuti e migrazione — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** tutti i contenuti del sito WordPress in Sanity, modificabili dallo Studio su `rggndr.sanity.studio`; home, footer e gallery del sito Astro letti da Sanity in fase di build; una pubblicazione in Sanity ricostruisce il sito da sola.

**Architecture:** lo Studio vive in `studio/`, un pacchetto npm separato (non un workspace), così la build del sito su Cloudflare non installa React e lo Studio. I tipi delle query li genera TypeGen in `src/content/sanity.types.ts`, che si committa. Il sito legge i contenuti da una sola funzione, `fetchQuery`, con due sorgenti: Sanity (build reale) oppure un dataset di prova in NDJSON valutato in locale con `groq-js` (test e CI). Le query sono identiche nei due casi. Le immagini passano da `@sanity/image-url`; nei test le richieste al CDN di Sanity vengono servite da file locali. La migrazione è uno script Node che legge la REST API del WordPress e scrive un NDJSON con id stabili, da importare con `sanity dataset import --missing`.

**Tech Stack:** Sanity 6.x (Studio, CLI, TypeGen), `@sanity/client` 8.x, `@sanity/image-url` 2.x, `groq` 6.x, `groq-js` 2.x, `node-html-parser` (solo nella migrazione), Astro 7, Playwright, Cloudflare Pages (deploy hook).

**Spec:** roadmap `docs/superpowers/plans/2026-11-16-roadmap-v1-v2.md` (M1, decisioni D1–D7), `CLAUDE.md`. Template WordPress di riferimento: `../rggndr-website/src/templates/{homepage,about,gallery}.php`, `../rggndr-website/src/single-progetto.php`, `../rggndr-website/src/template-parts/page/loop-contenuto-flessibile-progetto.php`.

## Cosa ho trovato prima di scrivere il piano

- La REST API del WordPress restituisce `"acf": []` per progetti e pagine: i campi ACF **non sono esposti**. Senza un intervento sul WordPress (Q1) lo script vede solo titolo, slug, immagine in evidenza e i dati Yoast (`yoast_head_json`: title, description, ecc.), che invece ci sono.
- Gli id dei paragrafi del manifesto (`#manifesto-1`, `#manifesto-2`) sono usati da `tests/reveal.spec.ts` e `tests/split-edge.spec.ts`: il rendering da Sanity deve conservarli.
- `astro/tsconfigs/base` ha già `allowImportingTsExtensions: true`: gli script Node in TypeScript possono importarsi con l'estensione `.ts` ed eseguirsi con `node` (rimozione dei tipi nativa da Node 22.18).
